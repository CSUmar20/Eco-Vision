# EcoVision

EcoVision is a mobile-first application that identifies a photographed household item and is being built to provide source-backed disposal guidance for the recycling program selected by the user.

The long-term product promise is:

> EcoVision identifies household items and reports whether the user's selected local recycling program accepts them, without tracking the user's precise location.

An item being technically recyclable does not mean every curbside program accepts it. EcoVision should therefore describe an item's status within a named municipality or waste program rather than call it universally recyclable.

## Current MVP

The current vertical slice can:

- Select an image from the device photo library or open the device camera.
- Preview the selected image.
- Upload JPEG, PNG, or WebP images up to 10 MB.
- Classify the image using a configurable Hugging Face zero-shot image model.
- Display the top prediction, confidence, and alternative predictions.
- Display source-backed general U.S. disposal guidance for a mapped material.
- Save the scan and its predictions in PostgreSQL.
- Let a guest confirm the top prediction or select one of the returned alternatives, then refresh
  the disposal guidance for the corrected material.
- Preserve the selected image and allow the user to retry after an error.

The implemented guidance is country-level and may recommend recycling, trash, donation, composting,
special drop-off, or checking locally. It does **not** determine whether a municipality, county, or
waste provider accepts the item. Jurisdiction-specific coverage remains unavailable until verified
local rules are curated and the mobile location flow is connected to them.

## Planned location-aware guidance

EcoVision does not need exact coordinates. A future onboarding or scan flow should ask the user for a general disposal area:

- Country
- ZIP or postal code, or a manually entered city and state/province
- Confirmed municipality or county
- Waste provider when multiple programs serve the same area

The application should store a normalized recycling jurisdiction rather than a precise address or live GPS trail. Local guidance should include its official source, the date it was last verified, and one of these states:

- Accepted curbside
- Not accepted curbside
- Special drop-off required
- Local rule unavailable or unclear

## Architecture

```text
Expo mobile app
    |
    | multipart image upload
    v
FastAPI /classify
    |
    +--> Pillow image validation
    |
    +--> Hugging Face CLIP zero-shot classification
    |
    +--> SQLAlchemy Scan model
              |
              v
         PostgreSQL 18
```

Repository layout:

```text
backend/
  app/                 FastAPI application, database model, and classifier
  evaluation/          Real-image classifier dataset, runner, and results
  migrations/          Alembic database migrations
  tests/               Isolated API and classifier tests
  .env.example         Backend environment template
  Dockerfile           Production API container

mobile/
  src/app/             Expo Router screens
  src/api/             Typed backend client
  src/config/          Mobile runtime configuration

compose.yaml           Local PostgreSQL service
```

## Prerequisites

- Python 3.12
- Node.js and npm
- Docker Desktop or another Docker-compatible runtime
- Xcode with an iOS Simulator for iOS development

The project currently targets Expo SDK 57 and uses an iOS Simulator-only development workflow. This avoids the Expo Go SDK mismatch on a physical phone and does not require a paid Apple Developer account.

## Initial setup

Clone the repository, then create the backend environment file:

```bash
cp backend/.env.example backend/.env
```

Replace the example PostgreSQL password in `backend/.env`. Keep this file local; it is ignored by Git.

Create the Python environment and install the locked backend dependencies:

```bash
cd backend
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements-lock.txt
cd ..
```

Install mobile dependencies:

```bash
cd mobile
npm install
cd ..
```

## Start the application

Run each component in a separate terminal.

### 1. PostgreSQL

From the repository root:

```bash
docker compose up -d postgres
docker compose ps
```

The database is exposed only on `127.0.0.1:5432` and stores its data in the `postgres_data` Docker volume.

### 2. Database migrations

From `backend/`, with the virtual environment activated:

```bash
alembic upgrade head
```

Useful migration commands:

```bash
# Show the current revision
alembic current

# Create a migration after changing SQLAlchemy models
alembic revision --autogenerate -m "describe the schema change"

# Revert one migration
alembic downgrade -1
```

Review autogenerated migrations before applying them. Do not edit a migration that has already been applied to a shared environment; create a new migration instead.

### 3. Baseline material catalog

Load or update the source-backed baseline material catalog before starting the API:

```bash
python -m app.seed_materials
```

The command is idempotent: existing baseline materials, aliases, and US general guidance are
updated in place, while locally added aliases are preserved.

### 4. FastAPI

From `backend/`:

```bash
source .venv/bin/activate
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Confirm the service is running:

```bash
curl http://127.0.0.1:8000/health
```

Expected response:

```json
{"status":"ok"}
```

Do not open the mobile app until this health check succeeds. If `curl` cannot connect,
the simulator will also report that it cannot reach the EcoVision API.

Interactive API documentation is available at `http://127.0.0.1:8000/docs`.

### Classifier evaluation

The backend includes a versioned set of 30 human-labeled household-item photographs from
Wikimedia Commons. The manifest records the exact image URL, checksum, author, license, source
page, and expected classifier label. Run the production classifier against that set from
`backend/`:

```bash
python -m evaluation.evaluate
```

The command downloads images to an ignored local cache, verifies every checksum, and writes a
JSON result plus a Markdown accuracy, confusion, and failure report under `evaluation/results/`.
Use `--offline` after the first run to guarantee that evaluation performs no network requests.

### Production container

Build the backend image from the repository root:

```bash
docker build --tag ecovision-api:local backend
```

The image installs the official CPU-only PyTorch build, then starts one Uvicorn process as a
non-root user. It listens on port `8000` by default and uses a platform-provided `PORT` value when
present. For example, when the supplied environment file contains a database URL that is
reachable from the container:

```bash
docker run --rm \
  --env-file backend/.env \
  --publish 8000:8000 \
  ecovision-api:local
```

The normal local `backend/.env` points to `127.0.0.1`, which means the container itself and will not
reach PostgreSQL on the Mac. Use an ignored, container-specific environment file with
`host.docker.internal` for that local test. A production host should inject `DATABASE_URL` through
its secret manager rather than copy an environment file into the image.

Database migrations and catalog seeding are release commands, not part of API startup. Run them
once per deployment before routing traffic to new replicas:

```bash
docker run --rm --env-file backend/.env ecovision-api:local alembic upgrade head
docker run --rm --env-file backend/.env ecovision-api:local python -m app.seed_materials
```

When the API is behind a trusted reverse proxy, set `FORWARDED_ALLOW_IPS` to only the proxy IPs or
networks supplied by the hosting provider. Do not trust forwarded headers from arbitrary public
clients.

### 5. Expo

From `mobile/`:

```bash
npm run ios
```

The iOS Simulator has no real camera hardware. Add a JPEG or PNG to the simulated photo library and use **Choose from library** when testing the scan flow.

### Mobile API address

The current iOS Simulator build always connects to `http://localhost:8000`. The
simulator shares the Mac's loopback interface, so FastAPI can remain bound to
`127.0.0.1`. Using the `localhost` hostname also matches the iOS local-network
transport exception without enabling insecure HTTP globally. A mobile environment
file is not used in this simulator-only workflow.

## API

### `GET /health`

Returns a basic process health response. It does not currently verify database or model availability.

### `GET /jurisdictions`

Searches active recycling jurisdictions by city, display name, state, county, waste provider, or
postal-code prefix. The required `query` parameter accepts 2–100 characters, and `limit` accepts
1–20 results. A postal code can return multiple jurisdictions because ZIP boundaries do not
reliably match municipal or county boundaries; the mobile app must let the user confirm one.

### `GET /jurisdictions/{jurisdiction_id}/rules`

Returns the jurisdiction and its source-backed disposal rules. Every stored rule includes a stable
material key, disposal status, official source title and URL, and verification timestamp. When no
rules have been curated, the endpoint returns `coverage_status: "unavailable"` and an empty list.

### `POST /classify`

Accepts a multipart image field named `file` and an optional `jurisdiction_id`. Supported media
types are JPEG, PNG, and WebP. Unknown or inactive jurisdictions are rejected before inference.

Successful responses contain:

- Scan ID and creation time
- Model identifier
- Top prediction, confidence, and canonical material mapping
- All alternative classifier predictions with canonical material mappings
- Source-backed disposal guidance for the top material

When a selected jurisdiction has a rule for the detected material, the response uses that rule and
sets `disposal_guidance.scope` to `"jurisdiction"`. Otherwise, it falls back to the matching
country-level general rule with scope `"general"`. Guidance is `null` when the classifier fallback
has no material mapping or no sourced rule is available.

### `PATCH /scans/{scan_id}/confirmation`

Accepts one of the labels returned for the referenced scan and saves it as anonymous model
feedback. The response includes the corrected canonical material and its applicable disposal
guidance so the client can update the result immediately. Labels that were not part of that
scan's predictions are rejected.

## Quality checks

Run backend checks from `backend/`:

```bash
.venv/bin/ruff check app tests migrations
.venv/bin/python -m pytest -q
```

The API tests replace the classifier and database session with deterministic fakes. They do not download or execute the Hugging Face model and do not require PostgreSQL.

Run the mobile TypeScript check from `mobile/`:

```bash
npx tsc --noEmit
```

## Known limitations

- The zero-shot classifier recognizes only the candidate categories currently defined in `backend/app/services/classifier.py`.
- Confidence is a model score, not a guarantee that the category is correct.
- Model quality has not yet been measured against a representative waste-item image set.
- The first real classification may be slow while the Hugging Face model is loaded or downloaded.
- Inference currently runs synchronously inside the API request.
- General disposal guidance is U.S.-level fallback guidance, not proof that an item is accepted by
  the user's curbside program or available local drop-off facility.
- The jurisdiction and rule schema exists, but no production jurisdiction dataset has been curated
  and the mobile location screen is not connected to the search endpoints yet.
- The application must not claim an item is locally accepted until an applicable rule has been verified.
- A saved scan-history interface is not implemented yet.
- The health endpoint does not check PostgreSQL connectivity or model readiness.
- Browser access from another LAN device may require additional development CORS configuration.

Model recognition quality should be evaluated separately with a small, labeled collection of real waste-item photographs. Recycling guidance should be evaluated against official municipality or waste-provider sources rather than inferred by the image model.
